# Мониторинг входящих предложений Yandex Pro

## Почему прежняя версия могла пропустить предложение

До этой реализации Android-код Yandex Pro был только диагностическим AccessibilityService. Он не определял и не показывал предложения. Серверный `MobileOrderWatcher` опрашивает доступный Fleet API и отправляет FCM лишь для заказов со статусами `assigned`, `waiting` и `in_progress`, привязанных к конкретному `driver_id`. Предложение на экране Yandex Pro может ещё отсутствовать в публичном Fleet API. Поэтому FCM-путь не гарантировал обнаружение входящего предложения. Без логов устройства и worker за 30 сентября 2026 года нельзя доказать, какой именно участок не сработал в конкретном случае.

## Путь события

`YandexNotificationListenerService` получает уведомления только из пакетов в `res/values/yandex_monitor.xml`. На устройстве проверьте фактическое имя пакета Yandex Pro; конфигурация сейчас содержит `ru.yandex.taximeter`, уже использовавшийся диагностическим сервисом. `YandexOrderDetector` оценивает фразы о заказе, цену, адрес, расстояние и время подачи. Событие со средней уверенностью попадает в журнал, но не показывается. Никакие отсутствующие поля не заполняются вымышленными значениями.

На проверенном Android 13 Yandex Pro прислал `title=Яндекс Про`, `text=Новый заказ` без цены и адреса. Точная отдельная фраза «Новый заказ» теперь считается подтверждённым предложением; общие упоминания заказа без деталей остаются только в журнале. Yandex Pro переиспользует один ключ уведомления для статусов «На линии», «Занят» и новых предложений. Локальный счётчик переходов отделяет следующие предложения с тем же ключом, а повторные обновления одного предложения сохраняют его `event_id`.

Подтверждённое событие сразу попадает в общий `OrderDelivery`, который проверяет водителя и настройки, сохраняет локальную дедупликацию и показывает существующий overlay поверх приложений. Если overlay недоступен, создаётся Android notification высокой важности. Затем `YandexAccessibilityService` считывает видимый экран Yandex Pro: тариф, тип заказа, цену, оплату, время в пути и подписанные адреса. `YandexOfferEnrichment` сопоставляет снимок с последним `event_id` и обновляет содержимое уже показанного overlay без второго показа. Неизвестные значения не придумываются. Нажатие резервного системного уведомления открывает Yandex Pro, если пакет доступен. Работа listener не зависит от открытого Flutter Activity. Android сам восстанавливает разрешённый NotificationListenerService после перезапуска; отдельный BOOT_COMPLETED receiver здесь не нужен.

В виджете локального предложения неизвестные адреса помечены «уточняется». Отдельные строки «Подача» и «До подачи» показывают минуты и километры из блока `км · мин` только при соседней подписи «Ближняя/Средняя подача». Время и расстояние поездки берутся только из явно подписанных полей и не заменяются показателями подачи. Сумма считается ценой поездки только при явной подписи «Цена», «Стоимость поездки», «Итого» и т. п.; доход, баланс, бонус и комиссия не используются. Валюта показывается только при наличии обозначения рядом с ценой. Оплата читается из подписанного поля и сохраняет различие между картой, безналом, наличными, корпоративным счётом и предоплатой. Когда цена, оплата или время поездки не опубликованы в предложении, виджет прямо сообщает «нет в предложении».

Кнопка действия в overlay следует цепочке `Принять → На месте → Поехали → Завершить`. `YandexActionController` принимает нажатие только при открытом окне `ru.yandex.taximeter`, совпадении текущей стадии и одной точно найденной видимой, активной кнопке с `ACTION_CLICK`. Обрезанное дерево Accessibility, неоднозначные кнопки или неподходящий экран приводят к сообщению «Не удалось выполнить действие» и кнопке «Открыть Yandex Pro» без автоматического нажатия. После успешного запроса overlay показывает «Подтверждаем...», а следующая стадия появляется только после наблюдения следующего экрана Yandex Pro. Закрытие overlay прекращает ожидание. Локальное предложение (`data_kind=incoming_offer`) и подтверждённый заказ Fleet API (`data_kind=confirmed_order`) различаются; обработчик предложения не копирует данные из позднего заказа без надёжного ID. Fleet API остаётся источником статуса подтверждённого заказа, а завершение реального заказа через локальную БД запрещено.

На присланной карточке Yandex Pro от 3 октября 2026 года показаны `3,9 км · 6 мин` рядом со «Средняя подача», точки «А» и «Б» с адресами, а также бонус `+100 ₽`. Парсер сохраняет повторяющиеся маркеры «А/Б» карты и карточки, ищет пару маркер–адрес именно в карточке и не выдаёт время подачи или бонус за время и цену поездки. Цена поездки и способ оплаты на этом снимке не видны; если их нет и в дереве Accessibility, виджет отмечает это и обновит поля только при появлении достоверных данных.

На карточке предложения от 4 октября 2026 года есть `1,9 км · 5 мин`, «Ближняя подача» и бонус `+130 ₽`, но нет цены поездки и способа оплаты. Фото чека после завершения этой поездки показывает `380 ₽` и безналичную оплату. Итог чека нельзя достоверно восстановить во время предложения из времени подачи или бонуса. Fleet API `orders/list` возвращает данные уже созданного заказа, а уведомление о предложении не содержит его ID; поэтому приложение не подставляет в ранний виджет цену или оплату другого заказа.

Независимый серверный worker продолжает опрос Fleet API с действующими настройками интервала и кэша. FCM остаётся data push с Android high priority и с тем же `type=new_order` ради совместимости с действующим приложением; передаются `event_type=incoming_order`, `data_kind=confirmed_order` и устойчивый `event_id`. Сервер использует существующую Firebase авторизацию, сессии, регистрацию FCM token и адресную отправку по `driver_id`.

## Как включить и проверить

1. Войти под учётной записью водителя и включить уведомления приложения в Android.
2. В приложении открыть **Настройки → Интеграция с Yandex Pro → Доступ к уведомлениям → Включить**. В системном списке разрешить доступ для Fleet Hub. Отдельно включить службу специальных возможностей Fleet Hub, разрешить уведомления Fleet Hub и отображение поверх других приложений, включить режим водителя, затем нажать **Проверить мониторинг**.
3. Включить **Режим отладки мониторинга**. Реальное уведомление Yandex Pro создаст записи `YANDEX_NOTIFICATION → ORDER_DETECTED → DEDUP → ORDER_DELIVERY → OVERLAY_SHOWN`, затем при видимой карточке `ACCESSIBILITY_DATA → ORDER_PARSED → OVERLAY_UPDATED`. Если Yandex Pro закрыт, виджет появится сразу без деталей; откройте карточку Яндекс Про, пока предложение активно, чтобы увидеть обновление. На карточке с `+130 ₽` на кнопке принятия эта сумма не является доказанной ценой поездки; если стоимость и оплата не раскрыты Яндекс Про, они остаются неизвестными. Значения `км · мин` рядом с «Подача» описывают прибытие к пассажиру, не длительность самой поездки. Проверить реальным заказом каждую кнопку overlay: после `ORDER_ACTION_REQUEST → ACTION_NODE_FOUND → ACTION_CLICK_SUCCESS` должна появиться запись `YANDEX_STATE_CHANGED` только при следующем экране. Для нарисованной кнопки без `ACTION_CLICK` используется касание строго по видимой надписи в окне Яндекс Про; в журнале указан `source=visible_label_gesture`. При отказе `ACTION_CLICK_FAILED` содержит причину, а виджет предлагает повторить или открыть Яндекс Про. После обновления APK включить сервис специальных возможностей заново, чтобы Android применил возможность жестов. `FLEET_STATE_CONFIRMED` относится только к данным официального Fleet API. Кнопка **Копировать** копирует мониторинг, а **Скопировать debug-log** ниже копирует отдельный Accessibility журнал. **Сохранить** открывает системное меню отправки текста. Журнал сохраняется между перезапусками, ограничен примерно 1 MB, очищается кнопкой **Очистить**.
   Для «Поехали» Яндекс Про может показывать слайдер. Если доступна его однозначная видимая область, сервис проводит жест слева направо (`source=visible_slider_gesture`); иначе действие отклоняется с причиной `slider_not_identified`.
4. На сервере проверить, что отдельно запущен ровно один `python -m app.mobile.worker`, `YANDEX_MOCK_MODE=false`, FCM настроен и устройство зарегистрировано. События `order_watcher_poll_*`, `new_order_detected`, `order_delivery_*` показывают серверный путь.

## Ограничения

- Если Yandex Pro не публикует системное уведомление о предложении или скрывает полезные сведения, listener не сможет увидеть или надёжно подтвердить заказ. Текст и package name зависят от версии Yandex Pro и требуют проверки на реальном устройстве.
- AccessibilityService видит содержимое карточки только когда окно Yandex Pro действительно открыто и предоставляет текст в Android accessibility tree. При закрытом или заблокированном Yandex Pro виджет всё равно открывается по уведомлению, но скрытые поля нельзя считать. Парсер не угадывает цену и адреса по другим экранам.
- Яндекс Про может не показывать точку Б для некоторых предложений без соответствующего режима доступа. В этом случае адрес назначения недоступен и остаётся «уточняется»: https://pro.yandex.ru/ru-ru/tula/knowledge-base/taxi/app/orders-search
- Дедупликация между локальным событием без order ID и поздним FCM возможна лишь при совпадении цены и адреса подачи в двух источниках в течение двух минут. Если этих полей нет или они отличаются, безопасно установить связь нельзя; может появиться второе уведомление. Автоматическое сопоставление только по времени или водителю было бы опасным для двух разных заказов.
- Fleet API не считается потоком пассажирских предложений. Его текущий интервал 10 секунд и кэш 10 секунд сохранены, чтобы не увеличивать нагрузку без подтверждения rate limits. Высокий приоритет FCM не означает гарантированной задержки доставки на каждом устройстве.
- Для проверки поведения при открытом, свёрнутом и закрытом Flutter, после reboot и при конкретной версии Yandex Pro нужен реальный Android телефон и реальное уведомление. Сборка и автоматические тесты этого не заменяют.
- Если Yandex Pro рисует кнопку только графикой и не даёт точный текст и `ACTION_CLICK` в дереве Accessibility, приложение откажется нажимать её. Это проверяется только на той версии Yandex Pro, которая установлена у водителя.

## Production API URL

Сборка по умолчанию использует `https://yandexfeetbackend21.pythonanywhere.com/api/v1/mobile`: этот адрес указан в `FleetApi`, README и документации развёртывания, а `/health/ready` ответил HTTP 200 при проверке 1 октября 2026 года. Второй адрес `yandexfeet21.pythonanywhere.com` тоже ответил HTTP 200, но проект не указывает его как backend мобильного приложения. Для другого окружения задайте `API_BASE_URL=https://.../api/v1/mobile ./build_fleet_hub_apk.sh`; скрипт проверит соответствующий `/health`.

# Мониторинг входящих предложений Yandex Pro

## Почему прежняя версия могла пропустить предложение

До этой реализации Android-код Yandex Pro был только диагностическим AccessibilityService. Он не определял и не показывал предложения. Серверный `MobileOrderWatcher` опрашивает доступный Fleet API и отправляет FCM лишь для заказов со статусами `assigned`, `waiting` и `in_progress`, привязанных к конкретному `driver_id`. Предложение на экране Yandex Pro может ещё отсутствовать в публичном Fleet API. Поэтому FCM-путь не гарантировал обнаружение входящего предложения. Без логов устройства и worker за 30 сентября 2026 года нельзя доказать, какой именно участок не сработал в конкретном случае.

## Путь события

`YandexNotificationListenerService` получает уведомления только из пакетов в `res/values/yandex_monitor.xml`. На устройстве проверьте фактическое имя пакета Yandex Pro; конфигурация сейчас содержит `ru.yandex.taximeter`, уже использовавшийся диагностическим сервисом. `YandexOrderDetector` требует фразу о новом заказе и независимый признак цены или адреса. При недостаточных данных он пишет диагностическое событие без карточки. Никакие отсутствующие поля не заполняются вымышленными значениями.

Подтверждённое событие проходит через постоянную локальную дедупликацию и создаёт Android notification высокой важности. Нажатие открывает Yandex Pro, если пакет доступен. Работа listener не зависит от открытого Flutter Activity. Android сам восстанавливает разрешённый NotificationListenerService после перезапуска; отдельный BOOT_COMPLETED receiver здесь не нужен. Full-screen intent не запрашивается: Android ограничивает его использование, а для входящего заказа достаточно системного уведомления.

Независимый серверный worker продолжает опрос Fleet API с действующими настройками интервала и кэша. FCM остаётся data push с Android high priority и с тем же `type=new_order` ради совместимости с действующим приложением; добавлены `event_type=incoming_order` и устойчивый `event_id`. Сервер использует существующую Firebase авторизацию, сессии, регистрацию FCM token и адресную отправку по `driver_id`.

## Как включить и проверить

1. Войти под учётной записью водителя и включить уведомления приложения в Android.
2. В приложении открыть **Настройки → Интеграция с Yandex Pro → Доступ к уведомлениям → Включить**. В системном списке разрешить доступ для Fleet Hub. Вернуться и нажать **Проверить мониторинг**.
3. Включить **Режим отладки мониторинга**. Реальное уведомление Yandex Pro создаст записи `YANDEX_NOTIFICATION → ORDER_DETECTOR → DEDUP/WIDGET`. Нажать **Копировать**, чтобы скопировать заголовок состояния и весь локальный журнал. **Сохранить** открывает системное меню отправки текста. Журнал сохраняется между перезапусками, ограничен примерно 1 MB, очищается кнопкой **Очистить**.
4. На сервере проверить, что отдельно запущен ровно один `python -m app.mobile.worker`, `YANDEX_MOCK_MODE=false`, FCM настроен и устройство зарегистрировано. События `order_watcher_poll_*`, `new_order_detected`, `order_delivery_*` показывают серверный путь.

## Ограничения

- Если Yandex Pro не публикует системное уведомление о предложении или скрывает полезные сведения, listener не сможет увидеть или надёжно подтвердить заказ. Текст и package name зависят от версии Yandex Pro и требуют проверки на реальном устройстве.
- Дедупликация между локальным событием без order ID и поздним FCM возможна лишь при совпадении цены и адреса подачи в двух источниках в течение двух минут. Если этих полей нет или они отличаются, безопасно установить связь нельзя; может появиться второе уведомление. Автоматическое сопоставление только по времени или водителю было бы опасным для двух разных заказов.
- Fleet API не считается потоком пассажирских предложений. Его текущий интервал 10 секунд и кэш 10 секунд сохранены, чтобы не увеличивать нагрузку без подтверждения rate limits. Высокий приоритет FCM не означает гарантированной задержки доставки на каждом устройстве.
- Для проверки поведения при открытом, свёрнутом и закрытом Flutter, после reboot и при конкретной версии Yandex Pro нужен реальный Android телефон и реальное уведомление. Сборка и автоматические тесты этого не заменяют.
